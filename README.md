# Customer Churn Prediction (PySpark)

An end-to-end PySpark pipeline that predicts subscription-customer churn from
behavioral, delivery, and support signals — the kind of data a meal-kit or
subscription business would use to power retention and customer-value
initiatives.

## Why this project

Built to demonstrate a full, working data engineering + ML pipeline: raw data
→ feature engineering → distributed model training → evaluation, entirely in
PySpark, mirroring how a churn/CLV model would actually get built and
evaluated in a production data platform.

## Dataset

`data/customers.csv` — 20,000 synthetic subscription customers generated by
`src/generate_data.py`, modeled on realistic subscription-business signals:

- **Engagement**: weekly deliveries, skipped weeks, app sessions, recipe swaps, days since last login
- **Service quality**: late deliveries, support tickets, ticket resolution time
- **Value/pricing**: average box price, discount on last order
- **Relationship**: tenure, loyalty tier, referrals, acquisition channel

The churn label is generated from a weighted combination of these signals
plus noise, so the relationships in the data are realistic but not
hand-fitted to the model — you can see below the model doesn't hit 100%,
which is the point.

## Pipeline

`src/churn_pipeline.py`:

1. Load CSV into a Spark DataFrame
2. Encode categoricals (`StringIndexer` → `OneHotEncoder`) and assemble a
   feature vector (`VectorAssembler`)
3. 80/20 train/test split
4. Train a `RandomForestClassifier` (PySpark ML, 150 trees, max depth 8)
5. Evaluate: accuracy, AUC, F1, weighted precision/recall
6. Report feature importances
7. Write metrics and a predictions sample to `output/`

## Results (this run)

| Metric | Value |
|---|---|
| Accuracy | 0.722 |
| AUC | 0.716 |
| F1 | 0.645 |
| Weighted precision | 0.709 |
| Weighted recall | 0.722 |

**Top predictive features:** weekly delivery frequency, app engagement
(30-day sessions), skipped weeks, recency of login, tenure, and discount
usage — the same levers a customer-value/retention team would actually pull
(delivery cadence, app engagement, pricing/discount strategy).

Exact numbers will vary slightly between runs (random split + random forest
seed) and are easy to push higher with more feature engineering, hyperparameter
tuning, or a gradient-boosted model — noted as a next step below.

## Run it yourself

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt

python src/generate_data.py      # regenerate data/customers.csv
python src/churn_pipeline.py     # train + evaluate
```

Requires Java 8/11/17/21 (for Spark) in addition to Python.

## Possible extensions

- Swap Random Forest for `GBTClassifier` and compare
- Add a feature store layer (e.g. Tecton-style point-in-time correctness) for
  time-windowed features like `weekly_deliveries_last_8w`
- Orchestrate `generate_data.py` → `churn_pipeline.py` as an Airflow DAG
- Push metrics to a monitoring dashboard for model-drift tracking

## Stack

Python, PySpark (DataFrame API + MLlib), pandas.
